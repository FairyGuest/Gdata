## 一、User Prompt

请你给我完成一个 NFT 集合出价服务系统（blur 风格）：出价面向整个 collection 全局生效，卖方自选名下 token 以出价金额成交，结算含按比例版税拆分。

任务环境：从空目录开始，主要技术栈为 TypeScript、Node.js、Fastify、SQLite。

任务约束：所有数据和外部参与者使用本地合成夹具或明确的本地依赖，不需要生产账号和真实业务数据。夹具以固定种子生成初始账本（collections 含版税配置、代币所有权、用户余额）；撮合与出价竞态一律以内部事务提交序号裁决，不依赖真实时钟或网络时序。以最小可验收实现为目标，不实现语义规格之外的抽象、优化或扩展。

语义规格：

- 正例
  - 出价与冻结：创建集合出价即冻结出价者等额余额（余额不足 409）；取消仅限创建者并解冻冻结额；已成交出价不可取消（409）——均带可区分 reason
  - 卖方自选成交：accept 时卖方显式指定自名下属于该 collection 的 token（不再持有则 409）；不支持部分成交，不做自动选价或自动选 token；所有权转移、买方冻结额扣减、版税拆分、卖方入账在同一 SQLite 事务内提交
  - 版税拆分与快照一致性：royalty = floor(bid × bps / 10000)，卖方得 bid − royalty，买方实付恒为 bid；拆分配置以出价创建时的 collection 快照为准，此后修改不影响已有出价；成交响应中的新所有者、成交价与拆分金额来自同一提交快照
  - 并存与竞态：同一 collection 多个出价并存互不影响；accept 与取消并发以提交序号串行化，恰有一个生效
- 负例
  - 不把撮合写成"先翻转出价状态再补账"：任一时刻账本守恒（可用与冻结两类余额变动之和 = 0，拆分之和 = 成交价）
  - 不以请求到达的时间戳裁决并发；以事务提交序号为准
  - 不私自加"部分成交""自动降价撮合"等语义；成交固定为卖方显式选定出价与 token

工程结构：工程边界至少覆盖契约解析、执行内核、状态适配、诊断接口，模块间的数据与错误契约要明确；提供独立的测试和配置层；不要把全部实现塞进一个文件，也不要为凑文件数拆空壳。

- `src/contract/`：出价/取消/成交参数解析，价格与资产存在性、卖方持有归属校验
- `src/kernel/`：撮合内核：冻结语义、事务边界、守恒断言、提交序号并发裁决
- `src/state/`：SQLite 账本（所有权、可用/冻结余额、出价簿）、collection 快照存取与迁移
- `src/diag/`：出价状态转移日志、每次成交的拆分明细与判定理由

验证：

- accept 进行中创建者取消出价（并发）：断言串行化结果确定、恰有一个生效，且账本守恒（成交生效则冻结额已扣减；取消生效则解冻且 accept 409）
- 版税非整除（bid=1003、bps=250）：断言 royalty=25、卖方得 978，与独立算术对照
- 同一 token 先后被两个不同出价 accept：断言第一次 200，第二次因卖方不再持有 409，所有权仅转移一次

测试质量：独立测试应断言具体结果及失败类别，不只检查"接口能调用"；参考答案不能全部由被测核心实现自身生成。

可诊断性：测试日志应保留能够重放问题的运行编号、关键中间状态和判断理由，适用的输入错误、状态冲突、资源耗尽与计算失败须可区分；不要把异常或未知状态统一返回成功。

错误分类：422 输入错误（价格非正整数、未知资产、token 不属于该 collection）；409 状态冲突（余额不足冻结、已成交/已取消、非创建者操作、卖方不持有、竞态落败——均带可区分 reason）；503 资源耗尽（锁等待超时）；500 计算失败（守恒断言失败）。每次撮合记录：运行编号、出价 id、状态转移、拆分明细与判定依据。

验收：提供依赖清单与一键验收脚本 `npm run accept`，按固定顺序演练上述全部场景，逐步打印请求、响应与判定，全部通过退出 0、任一失败非 0 退出并指出失败场景；README 写清错误语义与复现步骤，测试实际执行并报告结果。
