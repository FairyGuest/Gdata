## 一、User Prompt

请你给我完成一个 NFT 事件索引服务系统：按全局序号摄取 mint/transfer/sale 事件流，增量维护所有权与成交统计投影，支持幂等重放与任意高度重建。

任务环境：从空目录开始，主要技术栈为 TypeScript、Node.js、Fastify、SQLite。

任务约束：所有数据和外部参与者使用本地合成夹具或明确的本地依赖，不需要生产账号和真实业务数据。夹具以固定种子生成事件流与乱序/重复批次；事件按 seq 严格连续应用，投影为事件应用的纯函数；并发摄取以内部事务提交序号裁决，不依赖真实时钟或网络时序。以最小可验收实现为目标，不实现语义规格之外的抽象、优化或扩展。

语义规格：

- 正例
  - 严格连续应用：事件按 seq 严格递增应用；seq 跳号拒绝且投影停在最后一个连续 seq（reason=event_gap）
  - 幂等摄取：重复提交已应用 seq 的事件返回 409（duplicate_event），投影不变；同 seq 但事件内容与已存不一致同样 409（duplicate_event），不静默覆盖
  - 投影纯函数与重建：投影包含所有权映射、volume（Σ 成交价）、floor（历史最低成交价）、lastSale；rebuild(toSeq) 重建结果与增量应用逐位一致；查询响应携带 appliedSeq，所有权与统计来自同一快照
  - 转移合法性：transfer/sale 的 from 须为投影当前所有者，否则该事件整体拒绝（409，invalid_transition），appliedSeq 不前移，后续合法事件正常应用
- 负例
  - 不把重复或跳号事件静默吞掉或覆盖；必须显式拒绝且 reason 可区分
  - 不用"最后写入胜出"处理并发摄取；以事务提交序号裁决
  - 不把投影做成只能全量重建的只读副本；增量应用与重建两条路径都要在

工程结构：工程边界至少覆盖契约解析、执行内核、状态适配、诊断接口，模块间的数据与错误契约要明确；提供独立的测试和配置层；不要把全部实现塞进一个文件，也不要为凑文件数拆空壳。

- `src/contract/`：事件体解析与字段校验、seq 与类型提取
- `src/kernel/`：应用内核：连续性与转移合法性检查、事务边界、提交序号并发裁决
- `src/state/`：SQLite 事件日志与投影表存取、rebuild 支持与迁移
- `src/diag/`：appliedSeq 与拒绝原因的只读查询

验证：

- 并发重复提交同一 seq 事件：断言恰有一个成功与一个 409（duplicate_event），volume/floor 不重复计入
- 非法转移（from 非当前所有者）：断言 409（invalid_transition）整体拒绝，appliedSeq 不动，后续合法事件正常应用
- 重建一致性：含乱序与重复的夹具重放后，rebuild 到 2 个抽检高度与增量应用逐位一致

测试质量：独立测试应断言具体结果及失败类别，不只检查"接口能调用"；参考答案不能全部由被测核心实现自身生成。

可诊断性：测试日志应保留能够重放问题的运行编号、关键中间状态和判断理由，适用的输入错误、状态冲突、资源耗尽与计算失败须可区分；不要把异常或未知状态统一返回成功。

错误分类：422 输入错误；409 状态冲突；503 资源耗尽；500 计算失败——各类均带可区分的独立 reason。

验收：提供依赖清单与一键验收脚本 `npm run accept`，按固定顺序演练上述全部场景，逐步打印请求、响应与判定，全部通过退出 0、任一失败非 0 退出并指出失败场景；README 写清错误语义与复现步骤，测试实际执行并报告结果。
