## 一、User Prompt

请你给我完成一个 NFT 电子门票服务系统：按场次发售座位唯一的门票，支持转让、退票与检票，已检票为终态，限购额度与退票释放联动。

任务环境：从空目录开始，主要技术栈为 TypeScript、Node.js、Fastify、SQLite。

任务约束：所有数据和外部参与者使用本地合成夹具或明确的本地依赖，不需要生产账号和真实业务数据。夹具以固定种子生成场次（座位表）与用户余额；并发购票以内部事务提交序号裁决，不依赖真实时钟或网络时序。以最小可验收实现为目标，不实现语义规格之外的抽象、优化或扩展。

语义规格：

- 正例
  - 发售与座位唯一：同一场次同一座位至多一张有效票；并发抢购同一座位恰有一个成功；扣款与出票在同一 SQLite 事务内提交
  - 限购与释放：每人每场上限 limit 张（超限 409，purchase_limit_reached）；退票释放额度与座位，座位可再次发售
  - 转让：仅当前持有者可转让（409，not_holder）；已检票不可转让（409，already_checked_in）；已退票不可转让（409，voided）
  - 检票：检票校验当前持有者（409，not_holder）并进入终态；重复检票 409（already_checked_in）；检票仅锁定状态，不改变历史归属记录
- 负例
  - 不把"座位唯一"交给唯一索引报错兜底了事；须在事务内显式校验并返回可区分 reason
  - 不以请求到达的时间戳裁决并发抢座；以事务提交序号为准
  - 已检票/已退票的票不得经任何路径变更持有或再检

工程结构：工程边界至少覆盖契约解析、执行内核、状态适配、诊断接口，模块间的数据与错误契约要明确；提供独立的测试和配置层；不要把全部实现塞进一个文件，也不要为凑文件数拆空壳。

- `src/contract/`：购票/转让/退票/检票参数解析，场次座位与数量校验
- `src/kernel/`：售票内核：座位唯一性、限购、事务边界、提交序号并发裁决
- `src/state/`：SQLite 账本（座位表、票状态机、余额、限购计数）与迁移
- `src/diag/`：票状态与交易结果的只读查询

验证：

- 并发双买家购同一座位：断言恰有一个 200 与一个 409，出票仅一张，扣款守恒
- 限购边界：达上限后再购 409（purchase_limit_reached）；退票后额度与座位释放、可再次购入
- 状态机边界：已检票转让、已检票退票、重复检票——断言各自 409 且 reason 可区分

测试质量：独立测试应断言具体结果及失败类别，不只检查"接口能调用"；参考答案不能全部由被测核心实现自身生成。

可诊断性：测试日志应保留能够重放问题的运行编号、关键中间状态和判断理由，适用的输入错误、状态冲突、资源耗尽与计算失败须可区分；不要把异常或未知状态统一返回成功。

错误分类：422 输入错误；409 状态冲突；503 资源耗尽；500 计算失败——各类均带可区分的独立 reason。

验收：提供依赖清单与一键验收脚本 `npm run accept`，按固定顺序演练上述全部场景，逐步打印请求、响应与判定，全部通过退出 0、任一失败非 0 退出并指出失败场景；README 写清错误语义与复现步骤，测试实际执行并报告结果。

## 三、GSB

> 五段式：要求锚点 → A 评估 → B 评估 → 权衡 → 判定。

- **要求锚点**：prompt 要求"独立测试应断言具体结果及失败类别，不只检查'接口能调用'；参考答案不能全部由被测核心实现自身生成"，同时要求 npm run accept 按固定顺序演练全部场景。
- **A 评估**：座位唯一抢购、限购释放联动、检票状态机（含终态与重复拒绝）均已实现。**有独立测试层**（test/http.test.ts + test/kernel.test.ts，8 用例，npm test 指向真实测试），npm test 8/8 通过。验收方复跑 npm run accept 全场景 PASS、退出码 0（17 步含 reason 断言与所有权不可变断言）。四层 10 源文件、README 齐备。墙钟 1h40m、159 处 429。
- **B 评估**：同上语义全部实现且验收通过（npm run accept 全场景 PASS、退出码 0）。但**独立测试层缺失（S2）**：全仓库无 `*.test.ts`，npm test 别名至 npm run accept——被测方自写的验收脚本自我循环，违反"参考答案不能全部由被测核心实现自身生成"。墙钟 45 分钟、120 处 429，速度优势约 57%。
- **权衡**：两者功能语义与验收结果等价（均全绿退出码 0）。核心差异在**测试层**：A 的 8 个独立测试用例 + npm test 指向真实测试 vs B 的零测试文件 + 别名伪装。B 快了约一小时，但提速的来源就是砍掉了测试层的编写时间——速度与偷工是同一件事。测试质量条款是 prompt 明确要求的，缺失属于 S2 不可被速度抵消。
- **判定**：**A 更好**。交付完整性与验证真实性是首要维度；B 在该维度有 S2 缺失，其速度优势建立在省略明确要求的交付物之上。
